PAC代理脚本地址填在哪里？从自动检测到分流排查

仓老师机场观察2026-11-13— 次阅读
网络排障

PAC 地址要填在「使用设置脚本」或「自动代理配置 URL」里。Windows 的入口在「设置 → 网络和 Internet → 代理」。桌面浏览器如果使用自己的代理设置，就到浏览器里找对应选项。拿到的是代理服务器地址和端口的话，请用手动配置。

三种代理选项，分别需要什么？

设置 你需要提供什么 请求怎么走
自动检测 通常无需手填地址 通过 WPAD 等机制尝试发现当前环境提供的配置
使用设置脚本 PAC 脚本的完整地址 支持 PAC 的应用按脚本为请求选择代理或直连
手动代理 服务器地址和端口 按固定代理和已配置的例外规则处理请求

PAC 是代理自动配置脚本。它可以让一个域名走代理，另一个域名走 DIRECT，也就是直连。脚本里的直连指本次请求跳过该应用的代理，设备若另有活动的 VPN，还要看系统如何路由。机场订阅通常是给客户端导入节点或配置用的，遇到脚本地址栏，请向提供方确认对方给的确实是 PAC。

系统里填了，浏览器会用吗？

取决于浏览器的当前设置。以桌面 Firefox 为例，它有「使用系统代理设置」和单独的「自动代理配置 URL」。选了后者，就核对浏览器自己的地址，更新后还可以点「重新加载」。若配置由扩展或单位策略管理，先查看设置由谁控制。

Windows 也给单独的 VPN 连接提供代理设置入口。如果组织要求为这条 VPN 配置脚本，按单位说明在该连接的高级选项里设置。自己填的是服务器和端口，可以参考本站的HTTP 与 SOCKS5 代理设置指南核对协议。

脚本填对了，为什么有些网页还是打不开？

  1. 先查脚本能否获取。 用提供方给的原地址，确认它是否要求先连公司 Wi-Fi 或 VPN。脚本获取失败时，某些配置会回退到手动代理或直连，强制使用脚本的配置也可能直接报错。若该地址返回登录页或报错页，请让提供方确认访问条件和脚本地址。
  2. 再查脚本是否选中了代理。 在同一个浏览器里分别打开预期走代理和预期直连的页面。测速页刚好命中直连规则时，它显示的是自己那一次请求的出口。多刷新几次，也还是在测同一个目标。
  3. 最后核对代理入口。 如果脚本指向本机客户端，确认客户端已启动，监听地址和端口与配置一致。若只有退出客户端后才出问题，可以继续查残留系统代理的恢复方法。
